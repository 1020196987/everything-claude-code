**`$PATH`** 是 Linux、macOS 和 Unix 系统中一个**至关重要的环境变量**。

简单来说，它是操作系统的 **“命令搜索地图”**。

### 1. 核心作用：它解决了什么问题？
当你在终端（Terminal）中输入一个命令（例如 `ls`、`git`、`node` 或 `tsc`）并回车时，系统并不知道这个命令的程序文件具体藏在硬盘的哪个角落。

**`$PATH` 的作用就是告诉系统：**
> “别瞎找，就去我列出的这几个文件夹里找可执行文件。”

系统会按照 `$PATH` 中列出的**顺序**，从上到下依次在这些文件夹里查找你输入的命令。
- 如果找到了，就执行它。
- 如果把所有文件夹都找遍了还没找到，系统就会报错：`command not found: xxx`（找不到命令）。

### 2. 它长什么样？
如果你在终端输入 `echo $PATH`，你会看到类似这样的一长串字符：

```bash
/Users/username/Library/pnpm:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
```

**解读规则：**
- **冒号 `:` 是分隔符**：这一长串其实是由多个独立的文件夹路径组成的。
- 上面的例子代表系统会按顺序去以下文件夹查找命令：
    1. `/Users/username/Library/pnpm` (这是你刚才配置的 pnpm 全局目录)
    2. `/usr/local/bin`
    3. `/usr/bin`
    4. `/bin`
    5. ...等等

### 3. 为什么之前会报错 `ERR_PNPM_NO_GLOBAL_BIN_DIR`？
- 当你运行 `pnpm install typescript -g` 时，pnpm 把 `tsc` 这个程序下载到了 `/Users/username/Library/pnpm` 文件夹里。
- 但是，当时你的 `$PATH` 变量里**还没有**包含这个文件夹路径。
- 所以当你输入 `tsc` 时，系统去 `$PATH` 里列出的其他文件夹找了一圈，没找到，就报错了。
- **解决方案**：运行 `pnpm setup` 其实就是修改了配置文件，把 `/Users/username/Library/pnpm` 这个路径**添加**到了 `$PATH` 的最前面。

### 4. 为什么要用 `$` 符号？
- **`PATH`**：是变量的名字。
- **`$PATH`**：是 Shell 的语法，意思是“**取出** PATH 变量里存储的值”。
    - 就像编程里的 `getValue(PATH)`。
    - 所以 `echo $PATH` 的意思是“打印出 PATH 变量的内容”。
    - 而 `export PATH=...` 的意思是“给 PATH 这个变量赋值”。

### 5. 如何查看和验证？
你可以随时在终端运行以下命令来查看当前的搜索路径：

```bash
echo $PATH
```

**验证 `tsc` 是否可用：**
配置好 `$PATH` 后，你可以用 `which` 命令来查看系统到底在哪里找到了 `tsc`：

```bash
which tsc
```
如果配置成功，它会输出：
`/Users/username/Library/pnpm/tsc`
这就证明 `$PATH` 已经生效，系统能在该目录下找到命令了。

### 总结
- **`$PATH`** = 一个包含多个文件夹路径的列表。
- **功能** = 告诉终端去哪里找可执行的命令。
- **格式** = 路径之间用冒号 `:` 隔开。
- **重要性** = 如果没有它（或者路径不对），你安装的全球大部分命令行工具（如 node, git, tsc, python 等）都无法直接通过名字运行。

## .zshrc配置文件
```shell
# pnpm
export PNPM_HOME="/Users/username/Library/pnpm"
case ":$PATH:" in
  *":$PNPM_HOME:"*) ;;
  *) export PATH="$PNPM_HOME:$PATH" ;;
esac
# pnpm end
```

这段 Shell 代码的核心作用是：**智能配置 pnpm 的全局命令路径，确保你在终端任何地方都能使用 pnpm 及其全局安装的包，同时防止配置重复。**

以下是简单总结：

### 1. 核心目的
让系统知道去哪里找 `pnpm` 和你全局安装的命令（如 `tsc`, `eslint` 等）。如果不加这段，你安装完全局包后输入命令会报错 `command not found`。

### 2. 代码逻辑拆解
*   **`export PNPM_HOME="..."`**
    *   **做什么**：定义 pnpm 存放全局可执行文件的目录路径。
    *   **为什么**：告诉系统“pnpm 的家”在哪里。

*   **`case ":$PATH:" in ... esac`**
    *   **做什么**：这是一个**防重复检查机制**。
    *   **技巧**：通过在 `$PATH` 前后加冒号（`:$PATH:`），统一匹配格式，无论路径在开头、中间还是结尾都能准确识别。
    *   **逻辑**：
        *   **如果已存在**（匹配成功）：什么都不做 (`;;`)，避免路径无限叠加。
        *   **如果不存在**（匹配失败）：将该路径添加到 `$PATH` 的最前面 (`export PATH="$PNPM_HOME:$PATH"`)，确保优先使用 pnpm 的版本。

### 3. 为什么要防重复？
因为**每次打开新的终端窗口**，系统都会重新执行一遍配置文件。
*   **没有检查**：每开一次窗口，路径就叠加一次，导致 `$PATH` 变得极长且混乱，影响性能。
*   **有检查**：无论开多少次窗口，路径只保留一份，干净高效。

### 4. 一句话人话版
> “把 pnpm 的命令目录加入系统搜索列表，但如果已经加过了就别再加了，免得越积越多。”
