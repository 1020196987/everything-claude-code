### Package Manager Detection
### 包管理器检测

The plugin automatically detects your preferred package manager (npm, pnpm, yarn, or bun) with the following priority:
插件自动检测你首选的包管理器（npm、pnpm、yarn 或 bun），优先级如下：

1. **Environment variable**: `CLAUDE_PACKAGE_MANAGER`
1. **环境变量**: `CLAUDE_PACKAGE_MANAGER`
2. **Project config**: `.claude/package-manager.json`
2. **项目配置**: `.claude/package-manager.json`
3. **package.json**: `packageManager` field
3. **package.json**: `packageManager` 字段
4. **Lock file**: Detection from package-lock.json, yarn.lock, pnpm-lock.yaml, or bun.lockb
4. **锁文件**: 从 package-lock.json、yarn.lock、pnpm-lock.yaml 或 bun.lockb 检测
5. **Global config**: `~/.claude/package-manager.json`
5. **全局配置**: `~/.claude/package-manager.json`
6. **Fallback**: First available package manager
6. **回退**: 第一个可用的包管理器

To set your preferred package manager:
要设置你首选的包管理器：

```bash
# Via environment variable
export CLAUDE_PACKAGE_MANAGER=pnpm
# 通过环境变量
export CLAUDE_PACKAGE_MANAGER=pnpm

# Via global config
node scripts/setup-package-manager.js --global pnpm
# 通过全局配置
node scripts/setup-package-manager.js --global pnpm

# Via project config
node scripts/setup-package-manager.js --project bun
# 通过项目配置
node scripts/setup-package-manager.js --project bun

# Detect current setting
node scripts/setup-package-manager.js --detect
# 检测当前设置
node scripts/setup-package-manager.js --detect
```

Or use the `/setup-pm` command in Claude Code.
或在 Claude Code 中使用 `/setup-pm` 命令。

> ```bash
> # Clone the repo first

> # Option B: Project-level rules (only applies to current project)

> cp -r everything-claude-code/rules/* .claude/rules/
> ```
> **注意：** Claude Code 插件系统不支持通过插件分发 `rules`（[上游限制](https://code.claude.com/docs/en/plugins-reference)）。你需要手动安装规则：

> ```bash

## 🎯 Key Concepts
## 🎯 关键概念

### Agents
### 代理

Subagents handle delegated tasks with limited scope. Example:
子代理以有限范围处理委托的任务。示例：

```markdown
---
name: code-reviewer
description: Review code quality, security, and maintainability

You are a senior code reviewer...
```
```markdown

name: code-reviewer
description: 审查代码的质量、安全性和可维护性
tools: ["Read", "Grep", "Glob", "Bash"]
model: opus

```

### Skills
### 技能

Skills are workflow definitions invoked by commands or agents:
技能是由命令或代理调用的工作流定义：

```markdown
# TDD Workflow
# TDD 工作流

1. Define the interface first
1. 首先定义接口
2. Write failing tests (RED)
2. 编写失败的测试（RED）
3. Implement minimum code (GREEN)
3. 实现最少的代码（GREEN）
4. Refactor (IMPROVE)
4. 重构（IMPROVE）
5. Verify 80%+ coverage
5. 验证 80%+ 的覆盖率
```

### Hooks
### 钩子

Hooks trigger on tool events. Example — warn about console.log:
钩子在工具事件时触发。示例 - 警告 console.log：

```json
{
  "matcher": "tool == \"Edit\" && tool_input.file_path matches \"\\.(ts|tsx|js|jsx)$\"",
  "hooks": [{
    "type": "command",
    "command": "#!/bin/bash\ngrep -n 'console\\.log' \"$file_path\" && echo '[Hook] 移除 console.log' >&2"
  }]
}
```

### Rules
### 规则

Rules are always-follow guidelines, split into `common/` + language-specific directories:
规则是始终遵循的指南，分为 `common/` + 语言特定目录：

```

  common/          # Common principles (required)
  typescript/      # TS/JS specific patterns and tools
  python/          # Python specific patterns and tools
  golang/          # Go specific patterns and tools
  perl/            # Perl specific patterns and tools
```
```
~/.claude/rules/
  common/          # 通用原则（必装）
  typescript/      # TS/JS 特定模式和工具
  python/          # Python 特定模式和工具
  golang/          # Go 特定模式和工具
  perl/            # Perl 特定模式和工具
```

## ⚠️ Important Notes
## ⚠️ 重要说明

### Context Window Management
### 上下文窗口管理

**Critical:** Don't enable all MCPs at once. If too many tools are enabled, your 200k context window might shrink to 70k.
**关键：** 不要一次启用所有 MCP。如果启用了太多工具，你的 200k 上下文窗口可能会缩小到 70k。

Rule of thumb:
经验法则：
- Configure 20-30 MCPs
- 配置 20-30 个 MCP
- Keep fewer than 10 enabled per project
- 每个项目保持启用少于 10 个
- Keep active tools under 80
- 活动工具少于 80 个

Use `disabledMcpServers` in project config to disable unused ones.
在项目配置中使用 `disabledMcpServers` 来禁用未使用的。
